RAPIDS SQL Metrics Guide

This document is generated from the latest NVIDIA/cudf-spark main branch. It explains RAPIDS SQL metrics in Spark event logs and Spark SQL UI, including meanings, code locations, and bottleneck analysis guidance.

Important: The total/min/med/max suffixes in Spark UI are aggregation displays over tasks, not new metric names in code. For example, aggregation time total maps to aggregation time in code; aggregation time (excl. SemWait) is an auto-generated DEBUG companion metric.
Diagnostic configuration: Recommended diagnostic configuration: spark.rapids.sql.metrics.level=DEBUG. New op-time tracking is controlled by spark.rapids.sql.exec.opTimeTrackingRDD.enabled and is enabled by default.
Why can a DEBUG event log still miss some metrics? DEBUG only allows metrics and companion metrics to be created. Visibility still depends on whether the operator is in the plan, whether the file format/reader path applies, whether that code path ran, and whether the metric was updated to a non-zero value. For example, if GpuHashAggregate does not use a sort-based path, sort time and sort time (excl. SemWait) may not appear.
Why can raw total and excl. SemWait total be very different? For example, if Spark UI shows scan time total = 5.80h and scan time (excl. SemWait) total = 15.4min, most raw scan time is GPU semaphore queueing. Use the excl. SemWait value to estimate actual scan work, then inspect gpuSemaphoreWait for concurrency/resource tuning.

Limitations and Code Evidence

  • CPU fallback operators do not have RAPIDS operator timing; use explain/fallback reasons, Spark task CPU time, or CPU profiling.
  • Parent and child timing windows can overlap; do not blindly sum all visible metrics.
  • Missing (excl. SemWait) usually means metrics level is not DEBUG.
  • Driver-side metrics arrive via SparkListenerDriverAccumUpdates; task-side metrics arrive via SparkListenerTaskEnd.
  • nsTiming is nanoseconds; Spark timing is commonly milliseconds.
  • gpuSemaphoreWait is GPU permit queueing time; interpret it together with op time (excl. SemWait).

Code evidence: companion metrics, GpuOpTimeTrackingRDD, wrapWithTimeTrackingRDD, metrics level.

Eventlog Analysis Method

  1. Read SparkListenerSQLExecutionStart.sparkPlanInfo and build accumulator-id to operator/metric mappings.
